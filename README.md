# スポイト混色ナビ

写真の色をスポイトで拾い、手持ちの絵具の配合を逆算するiOSアプリ。

写真の上に指を置くと、指の少し上にルーペが出て、その場所の色を正確に読む。拾った色に近い配合を、ホルベインの油絵具111色・透明水彩18色それぞれから3案まで提示する。混色は加算（RGBの平均）ではなく、絵具の吸収と散乱を扱う減法混色（Kubelka-Munk）で予測するので、混ぜたときの濁りや明度の低下がそのまま出る。

油絵具は2026年11月2日現在の公式カタログ全色（単色107色＋カタログに単色掲載のないホワイト3色とアリザリンクリムソン）。色見本の原色と、パーマネントホワイトSFと1:1で混ぜた色の両方を、混色の予測に使っている。

パレットから5色を選ぶ「5色で作る」を入れると、その5色だけで配合を探す。同じ5色で写真全体を塗ったらどう見えるかを「仕上がり」で確かめられる。面化（Kuwahara）で細部を色の塊にしたうえで5色の色域へ寄せられるので、塗る前の見当をつけやすい。

## 画面

- 上部 60%：写真。ドラッグ中は指の40pt上に直径108ptの円形ルーペ（9×9画素の拡大＋十字照準＋色の表記）。仕上がりを出しているときは左上で「元の写真を見る」に切り替わる。
- 下部：拾った色と配合予測色のスウォッチ、色差（CIEDE2000）、絵具の切り替え（油絵具／透明水彩）、探す絵具の範囲（全色／定番18色）、5色の選択、仕上がりの切り替え、配合案3件（水平分割バー＋絵具名・顔料記号・比率）。
- 「色を選ぶ」：カタログ全色を系統（赤・橙・黄・緑・青・紫・茶黒・灰・金銀・アンティーク・白）で絞り、色名・品番・顔料で検索して5色を選ぶシート。各行に品番・乾燥日数・透明性を添える。
- 絵具の詳細：配合案の絵具名、または5色の枠を押すと、品番・系統・シリーズ・耐光性・乾燥日数・透明性・顔料・20ml参考価格と、混色の注意（N印）を出す。
- 最下部：AdMobバナー（テストID）。レシピはバナーの上に64ptの余白を取ってスクロールする。

## 色の扱い

1. **読み出し**：`PhotosPicker` から受け取った写真データを `CGImageSource`（ImageIO）で開き、Display P3 の `CGContext` に描き直してから画素を読む。端末の写真は P3 で記録されているため、sRGB に落としてから読むと鮮やかな色ほどずれる。向きは EXIF の `kCGImagePropertyOrientation`（1〜8）を `ImageGeometry.orientationTransform` の変換で焼き込む。`UIImage` の `imageOrientation` と `draw` は使わない——`CGContext` は左下原点なので、UIKit の描画を混ぜると上下・左右が反転する（build 11 までの不具合）。焼き込んだ1枚を表示・スポイト・ルーペ・仕上がりが共有するので、見えている写真と拾う色の向き・座標は必ず一致する。仕上がりを出しているときは、変換後の sRGB の画素から読む（見えている色を拾う）。
2. **座標**：`.scaledToFit` の表示矩形を自前で計算し、タッチ位置 → 画素座標を変換する（`ImageGeometry`）。
3. **Lab**：Display P3 → リニア RGB（sRGB と同じ伝達関数）→ XYZ（D65）→ CIELAB。行列と白色点は CIE の定義値。
4. **混色**：各絵具のマスストーン反射率から K/S を出し、散乱係数 S を掛けて吸収 K とする。混合は K と S を別々に線形結合し、`K/S` から反射率を戻す（2定数 Kubelka-Munk）。白の散乱が強いことを表現できるので、白で淡くした色が暗く転ばない。
5. **予測色**：混合した 36 バンドの反射率を、CIE 1931 2度視野＋D65 の重みで XYZ に積分し、Lab に直す。
6. **探索**：1色（100%）・2色（10%刻み9通り）・3色（10%刻み36通り）を候補にし、CIEDE2000 が小さい順に上位3案（同じ絵具の組み合わせは1案に統合）。指を動かしている間は2色までで軽く回し、指を離したときに3色まで探す。5色モードでは、その5色だけで同じ探索をする。
   - 全111色だと3色の組み合わせが23万通り・評価が804万通りになるため、Lab 空間で目標色に近い組を先に絞る（2色は線分、3色は三角形までの距離。減法混色は三角形より暗く出るので、目標色を持ち上げた位置からも見る）。絞ったあと 480組×9通りと最大1500組×36通りを実際に混ぜて評価する。
   - 24色以下（5色モード・定番18色）は絞らずに総当たりする。
7. **仕上がり**：写真を長辺800pxの sRGB に縮小し、面化 → 5色再現の順に掛ける。重い処理はバックグラウンドで回し、UIは固めない。
   - 面化：積分画像で 4 象限の平均と分散を出し、分散が最小の象限の平均を採る（Kuwahara）。半径は弱2・中3・強5画素。
   - 5色再現：sRGB 33×33×33 の格子点ごとに、選んだ5色の混色 455 通り（1〜3色・10%刻み）から Lab 最近傍の色の番号を先に求める（3D LUT）。画素ごとは格子のまわりの候補から Lab 距離で最も近い色を選ぶ。3次補間は速いが、補間した色が色域の外へ出る（実測で ΔE 17.8）ため採らず、出てくる色は必ず5色で作れる色にした。

### パレット

**油絵具111色**：カタログの単色107色（赤15・橙3・黄17・緑17・青18・紫7・茶黒13・灰8・金銀2・アンティーク7）と、カタログに単色の掲載がないパーマネントホワイトSF・チタニウムホワイト・ジンクホワイトSF、アリザリンクリムソンの4色。色名と顔料記号・品番・乾燥日数・透明性・耐光性・混色記号・20ml参考価格はカタログの一覧表のとおり。

**透明水彩18色**：チタニウムホワイト（PW6）、レモンイエロー（PY3+PW6）、カドミウムイエローペール（PY35）、イエローオーカー（PY42）、カドミウムレッドライト（PO20+PR108）、バーミリオンヒュー（PO73+PR254+PY110）、クリムソンレーキ（PR177+PR122+PV19）、オペラ（BV10+PR122）、ローシェンナ（PY42+PBr7）、バーントシェンナ（PBr7）、バーントアンバー（PBr7）、ウルトラマリンディープ（PB29）、コバルトブルー（PB28）、セルリアンブルー（PB35）、ビリジャンヒュー（PG7）、サップグリーン（PY150+PG7+PR122）、ペインズグレイ（PBk6+PB15+PR122）、アイボリブラック（PBk9）。

色データの出どころ（2026-11-22 確認）:

- 油絵具の色・品番・乾燥日数・透明性・耐光性・混色記号・価格：ホルベイン公式「油絵具カタログ」（2026年11月2日現在、全7ページ）。P2〜P4の色見本（左半分＝原色、右半分＝パーマネントホワイトSF 1:1混色）を300dpiで描画して中央値を sRGB として採り、P5〜P6の一覧表とP7の価格表を文字と座標から読み取る（`scripts/extract_catalog.py`）。
- カタログ自身の注記どおり、色見本は画面・印刷の環境で変わる。実際の絵具の色とは差がある。
- カタログに単色の掲載がないホワイトとアリザリンクリムソンは、公式 TDS（[HOC](https://www.holbeinartistmaterials.com/wp-content/uploads/2020/12/HOCTDS.pdf) / [HWC](https://www.holbeinartistmaterials.com/wp-content/uploads/2020/12/HWCTDS.pdf)）の値。透明水彩は TDS と公式カラーチャートから。
- 分光反射率は 380-730nm / 10nm の 36 バンド。原色と白1:1混色の両方の見本に合うよう、平滑な基底関数で反射率と散乱係数を当てはめた**近似値**で、実測の分光データではない（原色の当てはめは中央値 ΔE 0.002・最大 5.8、白混色は中央値 0.28・最大 7.0）。
- 散乱係数はパーマネントホワイトSFを 1.0 とした相対値。白1:1混色の見本が淡まり方の手本になっている。
- 反射率と Lab は同じ反射率から出しているので、スウォッチの色と「その絵具100%」の予測色は必ず一致する。
- 金属色（ゴールド・シルバー）は Kubelka-Munk の前提から外れるので、原色の見本だけに合わせ、混色の予測は目安として扱う。カタログには透明性の記号がないため、アプリでは「不透明」と表示する。

### 作例（全111色での上位案）

| 拾った色 | 1位 | 色差 |
| --- | --- | --- |
| 空の青 `#6E9BC5` | ライトマゼンタ10% + ブルーグレイ70% + ジンクホワイトSF20% | ΔE 0.6 |
| 若葉 `#7FA05A` | シナバーグリーン30% + グレイオブグレイ70% | ΔE 0.8 |
| 肌の明部 `#E8C4A8` | シェルピンク70% + アンティークイエローNo.2 20% + チタニウムホワイト10% | ΔE 1.3 |
| テラコッタ `#B96A47` | ブリリアントピンク60% + アイボリホワイト10% + イエローオーカー30% | ΔE 0.4 |
| 夕暮れの紫 `#6B5B8E` | ウルトラマリンブルー10% + ミスティブルー30% + ライトマゼンタ60% | ΔE 0.8 |

全色では、カタログにある既製の淡色（ミスティブルー、グレイオブグレイ、シェルピンクなど）が選ばれやすい。白を混ぜて作る配合にしたいときは、範囲を「定番18色」に切り替える（同じ空の青は コバルトブルーヒュー10% + パーマネントホワイトSF90% で ΔE 5.2）。

## 生成と検証

```sh
python3 scripts/extract_cie_data.py        # CIE の等色関数・D65 を 10nm に切り出す
python3 scripts/generate_spectral_data.py  # Sources/SpectralData.swift
python3 scripts/extract_catalog.py         # カタログPDF -> scripts/catalog/oil_catalog.json
python3 scripts/generate_palette.py        # Sources/PaletteData.swift
python3 scripts/generate_icon.py           # Resources/.../AppIcon.png
python3 scripts/verify_color_math.py       # 数値検証
```

`verify_color_math.py` は Swift 実装と同じ式を Python で書き直して突き合わせる。直近の結果（2026-11-22、build 12、98項目すべて合格）:

| 項目 | 結果 |
| --- | --- |
| sRGB 白 / 赤 / 緑 / 青 → Lab | 基準値と一致（±0.02） |
| sRGB → Lab → sRGB の往復 | 最大誤差 1.8e-07 |
| 分光 R=1 → XYZ | D65 白色（10nm 近似で 100.00 / −0.06 / 0.04） |
| CIEDE2000（Sharma 2005 の34ペア） | 最大誤差 5.0e-05 |
| 白+黒 50:50 | L\* 35.1（線形平均 49.5 より暗い＝濁りが出る。カタログの1:1見本と一致） |
| 赤30 + 白70 | L\* 56.0・a\* 68.8 の淡いピンク |
| 黄50 + 青50 | 緑（a\* −41.4、b\* +15.3、L\* 33.8） |
| 定番18色すべてを目標に | 全色 ΔE 0.01 以下で配合が見つかる |
| 全111色（絞り込みつき） | 各色 ΔE 0.01 以下で自分の色に戻る |
| 既知の3色混色 8通り | ΔE 1.5 以下で再現（絞り込みが正解を落とさない） |
| 絞り込みと総当たり | 30色で最良 ΔE が 0.5 以内で一致 |
| カタログの件数・系統・乾燥・透明性・耐光・価格 | 107色すべて表と一致（乾燥 I〜IV、透明性4段階、20ml価格はシリーズ表と一致） |
| カタログの色と Swift の Lab | 最大 ΔE 5.8（暗い色） |
| 白1:1混色の予測とカタログの見本 | 中央値 ΔE 0.28・最大 7.0 |
| 反射率から再計算した Lab | 埋め込んだ値と ΔE 0.1 以下 |
| 5色限定の探索 | 5色以外は混ざらず、全色の最良より悪くならない |
| 5色の 3D LUT | 格子点・変換後の色はすべて5色の混色（455通り）そのもの |
| 色域外の純色（緑・マゼンタ・青・シアン） | 彩度が下がり、色域の内側に収まる |
| 面化 | 一様な面は不変、エッジは中間色を作らず、ムラが減る |
| 面化＋5色再現 | 出力はすべて5色の混色そのもの |
| 写真の向き（EXIF 1〜8） | Swift の変換表を読み出して描き、8通りすべて表示の向きと一致（縦横の入れ替えも） |
| 向きとタップ | どの向きでも、表示の中央を触ると元画像の中央の画素を拾う |

Swift 側はこの環境に Xcode がないため、数値は上記の 1:1 ミラーで確認し、コンパイルは GitHub Actions で確認する。

## ビルド

```sh
xcodegen generate
xcodebuild build -project ColorMixNavi.xcodeproj -scheme ColorMixNavi \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO
```

`CURRENT_PROJECT_VERSION` は CI が `github.run_number` で上書きする。build 12 が写真の向き（EXIF）を焼き込む修正の版（build 9 がカタログ全色・色の詳細・全色対応の探索）。

## TestFlight 配信

`.github/workflows/ios-build.yml` が `main` への push で `scripts/ci-testflight.sh` を実行し、アーカイブ → 書き出し → TestFlight へアップロードする。ビルド番号は `github.run_number`。
